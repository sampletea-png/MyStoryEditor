# 实施个人小说编辑器 MVP

Parent: [规划个人小说编辑器 MVP](https://github.com/sampletea-png/MyStoryEditor/issues/1)

本规格把已清地图上的决策收成可建造合同。产品验收句仍以 `docs/mvp-spec.md` 为准；阶段切分以 `docs/roadmap.md` 为准；领域词以 `CONTEXT.md` 为准；技术约束以 `docs/adr/0001-tauri-tiptap-sqlite.md` 为准。不重开产品决策。

## Problem Statement

作者需要在本机 Windows 上写一部小说，同时把角色、地点、事件和设定放在手边查阅，而不把写作拆成一堆互不相通的文档。现有开源工具要么偏写作、要么偏世界观库，作者要在两者之间来回复制。作品必须是资源管理器能整夹带走的数据包，断网也能写、能保全、能导出。

## Solution

做一个单人、本地优先、无需账户的 Windows 桌面应用（显示名「小说编辑器」）。作品库是唯一入口；一部作品一份数据包。写作区是邻侧三栏：卷章树、正文、本章关联 / 设定查阅。作者可以先建资料再写正文，也可以先写再补设定。通用关联显式、双向、一对一条。作品总图只做一张底图加地点标记和故事线走线。自动保存、整部作品恢复点、正文导出和可再导入的作品归档保证能保全和带走。

## User Stories

1. As an 作者, I want 在未安装 WebView2 的电脑上启动时看到安装提示, so that 应用不会空白崩溃、我知道要装什么。
2. As an 作者, I want 第二次启动只唤起已有窗口, so that 不会出现第二个可写实例改坏同一部作品。
3. As an 作者, I want 断网后仍能打开已有作品、编辑、自动保存、创建恢复点、导出正文、导入作品归档, so that 创作不依赖网络。
4. As an 作者, I want 首次启动时指定或确认作品库位置, so that 作品落在我能看见的本地目录，而不是藏进 AppData。
5. As an 作者, I want 打开应用后进入作品库列表而不是某部作品, so that 作品库是进入作品的唯一入口。
6. As an 作者, I want 同时只打开一部作品, so that 回作品库才能换作品，避免多部并行写乱。
7. As an 作者, I want 默认作品库在「文档\小说作品库」, so that 第一次不用自己想路径。
8. As an 作者, I want 打开另一作品库只改指向, so that 原库原封不动。
9. As an 作者, I want 移动当前作品库时带走作品、恢复点和作品库回收区, so that 换盘不丢保全。
10. As an 作者, I want 每部作品是 `work.json` + `work.sqlite` + `assets\` 的独立文件夹, so that 我能用资源管理器整夹复制。
11. As an 作者, I want 新建作品时只填名称并立即打开「第一章」, so that 马上能写，不必先填简介作者封面。
12. As an 作者, I want 改作品名称不改文件夹名, so that 外部路径保持稳定。
13. As an 作者, I want 把数据包文件夹复制到同一作品库另一位置后得到另一部可打开的作品, so that 复制即副本，内部身份不同。
14. As an 作者, I want 删除作品先进入作品库回收区, so that 误删还能恢复。
15. As an 作者, I want 永久删除作品时经过不可撤销警告并删掉该作全部恢复点, so that 带走的同时不留残骸。
16. As an 作者, I want 一次只编辑一章, so that 光标、滚动和自动保存都围着当前章转。
17. As an 作者, I want 再次打开作品时回到上次章节、光标和滚动位置, so that 接着上次写。
18. As an 作者, I want 在卷章树新建、重命名、排序、移动、删除卷和章, so that 结构跟着稿走。
19. As an 作者, I want 新章节默认插在当前章之后（选中卷时追加到卷末）, so that 插入位置可预期。
20. As an 作者, I want 章节只存自由标题、编号由排列位置推导, so that 重排不必改标题里的数字。
21. As an 作者, I want 卷、章允许重名或空名，空名显示「未命名卷 / 未命名章节」, so that 还没起名也能继续写。
22. As an 作者, I want 作品要么直接包含章节、要么由卷包含章节, so that 两种结构不混用。
23. As an 作者, I want 创建第一个卷时把已有章节移入该卷, so that 从无卷切到有卷不丢章。
24. As an 作者, I want 「取消分卷」把所有章节提升到作品下, so that 可以退回扁平结构。
25. As an 作者, I want 删除卷时把卷及其中章节整体移入作品回收站, so that 误删能整组回来。
26. As an 作者, I want 恢复卷章时优先还原原位置、无法还原则追加到最近有效层级, so that 恢复结果可预期。
27. As an 作者, I want 删除最后一章后看到空状态且不自动补建「第一章」, so that 空作品是合法状态。
28. As an 作者, I want 给章节标「初稿 / 修订中 / 定稿」, so that 我知道这一章写到哪一步。
29. As an 作者, I want 用段落、粗体、斜体、删除线、分隔线写正文, so that 有轻量所见即所得，没有复杂排版打扰。
30. As an 作者, I want 段首缩进只是显示、不写入正文, so that 导出和字数不受假空格污染。
31. As an 作者, I want `Enter` 新建段落、`Shift+Enter` 插入段内换行, so that 分段和换行分开。
32. As an 作者, I want 粘贴外部内容只保留基础格式并清掉字体字号颜色, so that 网页粘贴不会弄脏稿面。
33. As an 作者, I want 另提供粘贴为纯文本, so that 我能主动丢掉全部样式。
34. As an 作者, I want 用粘贴而不是导入 TXT / Markdown / DOCX 来带入已有文字, so that 首版不接他方工程文件。
35. As an 作者, I want 实时看到本章和整部作品字数, so that 我知道写了多少。
36. As an 作者, I want 「你好，世界 Hello」计为 11 字（除空白外的字符，含中英文和标点）, so that 中英文混排字数可预期。
37. As an 作者, I want 正常输入中间隔不超过约 3 秒自动保存, so that 不用惦记存盘。
38. As an 作者, I want `Ctrl+S` 立即落盘, so that 关键时刻能强制保存。
39. As an 作者, I want 自动保存不抢焦点、不跳光标与选区, so that 打字不被打断。

## Implementation Decisions

- 栈保持已决：Tauri 2 + React + TypeScript + Tiptap MIT 核心；每作品一份 SQLite 与 `assets`；应用偏好在 `%APPDATA%`，不进作品库。用户让这项默认成立。
- 库结构版本（`PRAGMA user_version`）与正文 JSON 的 `document_schema_version` 分开。打开作品做结构迁移前先打恢复点（阶段 5 接上后强制执行；阶段 2/3 的迁移已经发生在已有作品上）。
- 阶段 1（能开能写）与阶段 2（设定资料）已在 `develop` 合入。阶段 3（关联、邻侧查阅、`Ctrl+K`）代码已在工作区，尚未作为收口提交。阶段 4（地点总图）与阶段 5（保全与带走）尚未开工。建造票按路线图竖切，不重做已合入阶段，除非验收句失败。
- 测试与实现共用三道已有缝，不新开模块边界。用户让这项默认成立：
  1. `AppApi`（内存实现与 Tauri 实现同一接口）是用户可感知写操作的最高缝。
  2. 领域纯函数覆盖卷章、自动保存、字数、粘贴清洗、地点树、故事线收录、关联配对、短查询回退等无 I/O 规则。
  3. Rust `WorkPackage` 与 schema 迁移覆盖落盘、搜索和跨版本打开。
- 字数规则以规格为准：除空白外的字符，「你好，世界 Hello」= 11。Rust 侧若仍按 10 断言，跟规格对齐，不另开计数口径。用户让这项默认成立。
- 通用关联无向、一对一条、可选说明；可关联种类为章节、角色、地点、事件、设定条目。故事线不入此表。删除并永久清除对象时丢掉其关联。
- 作品内搜索：章节标题 / 正文一组，设定名称 / 别名 / 摘要一组。FTS5 对 1–2 字中文不够用时必须子串回退，不能假定 trigram 够用。
- 地点总图坐标相对底图固有宽高归一化；命中在图像空间计算，显示按 object-fit: contain 回投。可丢弃原型用显示矩形百分比打点，那只演示交互，不采用为存储模型。路线图验证门（100% / 150% 各拖一次，再换不同比例的图）是通过条件。
- 一部作品至多一张底图。换图丢旧图；清图丢全部标记，地点树不动。走线只连已定点事件；事件链含未定点事件；多地点事件取最先关联的地点。
- 恢复点用 SQLite Backup API / `VACUUM INTO`，禁止热拷贝打开中的库。恢复点在数据包旁，不内嵌其他恢复点。默认恢复为新作品。
- 作品独占锁：同一数据包同时一处可写；进程消失后锁释放。
- 正文导出用 MIT 库从编辑器 JSON 生成 Markdown / 纯文本 / DOCX。禁止 Tiptap Pro 导出包。
- 作品归档是 `.storyarchive` ZIP，字段与数据包相同，含作品回收站，不含恢复点。导入只创建新身份。
- 进程单实例继续用已接入的单实例插件；缺 WebView2 时提示安装。
- 首版无自动更新器；不实现 AI 入口或接口。
- 外观保持单一浅色写作主题。样式微调视为可逆默认，不升级为产品决策。

## Testing Decisions

- 好测试只断言用户可感知行为或已写入规格的规则，不锁内部函数名、DOM 结构和 SQL 文本。
- 优先在已有最高缝上加行为：`AppApi` 内存实现覆盖跨界面用例；领域纯函数覆盖规则；Rust `WorkPackage` 覆盖落盘、迁移、搜索、备份否决。能在 `AppApi` 说清的，不在组件里再测一遍。
- 已有同类测试是样板：内存 API 的设定 / 关联 / 搜索块；领域里的地点树、故事线、关联配对、短查询；Rust 的打开恢复、分类迁移、关联去重。新阶段沿用这三层，不另起测试框架。
- 阶段验证门先于该阶段界面：搜索回退先于命令面板收口；坐标归一化先于往库里写第一个标记；Backup API 与热拷贝否决先于恢复点界面；损坏夹具先于「从恢复点恢复」界面；MIT DOCX 先于导出界面。
- 手工验收句在 `docs/mvp-spec.md`。自动化通过不是规格通过条件，但建造票必须以这些句子为完成定义。桌面端（`npm run tauri dev`）点验不能用浏览器内存库代替。
- IME 组字、干净 Win10 无 WebView2、Word / WPS 打开 DOCX、系统缩放 100% / 150% 标点不漂，仍是人工环境项；自动化只保证规则与落盘。

## Out of Scope

本规格不实现 `.scratch/novel-editor-mvp/leftovers.md` 里 **Open** 的条目。那份文件是唯一清单；这里只作索引：

- 云同步、多人协作、移动端、账户与加密
- AI 入口或接口
- 完整自定义字段模板；跨作品共享
- 系列管理；独立场景层级；整书连续滚动
- 多作品 / 多章节标签页、多窗口
- 写作向版本历史
- 复杂排版与正文插图
- 角色数值 / 库存 / 专用关系字段
- 正文选中自动建关联或插入标记
- 跨作品搜索、正则、批量替换
- 每日目标与写作统计图表
- 完整地图绘制器、分地点附图、地图上画通用关联
- 为各类资料各建独立分区主页
- 导入他方工程或把 TXT / Markdown / DOCX 导入为章节
- 自动更新器
- 用作品回收站删除整部作品
